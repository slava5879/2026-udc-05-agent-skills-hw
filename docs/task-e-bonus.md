# Task E (bonus) — Path 1: cross-tool portability check

**Що перевіряємо:** чи той самий скіл `creating-widget`, **без жодних змін**,
підхоплюється з двох різних місць — крос-tool конвенції `.agents/skills/` і
нативної для Claude Code теки `.claude/skills/`.

**Порівнювані розташування:**
- Tool 1 — Claude Code, скіл у `.agents/skills/creating-widget/` (конвенція, яку
  просить walkthrough)
- Tool 2 — Claude Code, копія в `.claude/skills/creating-widget/` (нативний шлях)

**Промпт (однаковий):** change request із `materials/ab-task.md` — додати `alert`
widget.

## Копія справді немодифікована

Скіл скопійовано як є; ідентичність доведена хешем вмісту, а не на око:

```bash
$ git hash-object .agents/skills/creating-widget/SKILL.md \
                  .claude/skills/creating-widget/SKILL.md
ca0f09b41eb6535c9870a3beb20ad20b7a67f90d
ca0f09b41eb6535c9870a3beb20ad20b7a67f90d
```

`diff -r` між теками порожній. Жодних tool-specific правок не знадобилось —
frontmatter `name` + `description` той самий в обох місцях.

`.gitignore` спеціально дозволяє дзеркало (`.claude/*` + `!.claude/skills/`), тож
у коміт потрапляє лише `SKILL.md`, а `.claude/settings.local.json` лишається
проігнорованим — перевірено `git check-ignore`.

### Що показав Tool 1 (реальні дані з прогону A, 2026-08-11 15:42)

Агент застосував скіл без згадки про нього в промпті — але з транскрипту видно,
**як саме** він до нього дійшов:

> This repo has a `creating-widget` skill — let me read it and the seeded
> `badge` widget.

Перед цією реплікою в транскрипті — `Read` і `Bash` (орієнтація в репо), після
неї — звичайний `Read` файлу `SKILL.md`. **Виклику скіла як зареєстрованого
інструмента (`Skill`) у транскрипті немає** — ні в цьому прогоні, ні в двох
прогонах B.

Тобто з `.agents/skills/` скіл спрацював **через файлову розвідку**: агент
побачив теку в дереві репо, здогадався за назвою, що це скіл, і прочитав його як
звичайний markdown. Це працює, але має наслідки:

- скіл підхоплюється лише тоді, коли агент і так оглядає дерево;
- `description` у frontmatter у цьому режимі не виконує своєї головної ролі
  (дешевого «завжди в контексті» тригера) — його читають уже **після** того, як
  файл відкрито;
- прогресивне розкриття вироджується: замість «опис завжди, тіло за потреби»
  виходить «нічого, поки не наткнувся, потім усе одразу».

### Що показав Tool 2 (проба 2026-08-11 16:27)

У новому чаті на запит «перелічи скіли, які тобі зараз доступні» агент відповів
за **один хід, без жодного виклику інструментів** — тобто список був у нього
вже на старті сесії. `creating-widget` у ньому є, з тим самим описом, що й у
frontmatter:

> **creating-widget** — золотий шлях додавання віджета в `app/` (чиста фабрика
> в `app/src/widgets/<name>/<name>.ts`, самореєстрація через `register()`,
> колокований vitest-тест, імпорт в `app/src/widgets/index.ts`)

**Контрольна група вийшла сама собою.** У цьому репо три скіли, але дзеркало
зроблено лише для одного. У списку доступних:

| Скіл | Де лежить | У списку зареєстрованих |
|---|---|---|
| `creating-widget` | `.agents/skills/` **+ `.claude/skills/`** | ✅ так |
| `architecture-deep-dive` | лише `.agents/skills/` | ❌ ні |
| `analyzing-bundle-size` | лише `.agents/skills/` | ❌ ні |

Агент навіть підсумував це сам: «creating-widget — єдиний скіл, який належить
цьому репо; решта — глобальні/плагінні». Два інші скіли цього ж репо він просто
не побачив.

Це прямий доказ: **Claude Code реєструє `.claude/skills/` і не реєструє
`.agents/skills/`.** Різниця не у вмісті файлу (він байт-ідентичний), а
виключно в розташуванні.

## Висновок

Скіл **портативний як файл**: жодних правок під інструмент не знадобилось, копія
байт-ідентична, і в обох розташуваннях він дав однаковий результат роботи.

Але портативність файлу ≠ портативність механізму, і це головна знахідка.
З `.claude/skills/` скіл **зареєстрований**: його `description` у контексті
агента з першої секунди, тому тригер спрацьовує саме так, як задумано
прогресивним розкриттям — дешевий опис завжди, важке тіло лише за потреби.
З `.agents/skills/` той самий файл підхоплюється **лише розвідкою дерева**:
спрацювання залежить від того, чи агент узагалі загляне в теку, а `description`
читається вже після відкриття файлу — тобто економія контексту зникає. Два інші
скіли репо, що живуть тільки в `.agents/skills/`, взагалі не потрапили до списку
доступних.

**Практичний висновок:** `.agents/skills/` варто тримати як канонічне,
tool-agnostic джерело (воно й лишається місцем, куди дивиться рев'ю домашки),
але для кожного інструмента обов'язково робити дзеркало в його рідну теку.
Для Claude Code це `.claude/skills/` — і без нього скіл не мертвий, але
деградує з «завжди видимого тригера» до «файлу, який пощастить прочитати».
Прикладна дія для цього репо: якщо покладатись на автозастосування, дзеркалити
треба всі три скіли, а не один.
